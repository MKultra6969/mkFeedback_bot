# feedback_bot для Telegram Serverless

Бот простой обратной связи: пользователи пишут боту — сообщения уходят
владельцу и администраторам, те отвечают прямо из чата. Полностью работает на
**Telegram Serverless**: без серверов, хостинга и внешних баз — только
V8-изоляты Telegram, встроенная SQLite и CLI `tgcloud`.

## Что умеет

**Для пользователей**
- Любое сообщение (текст, фото, видео, кружки, голосовые, документы, стикеры,
  геопозиция) уходит администраторам.
- Ответ приходит в тот же чат — как сообщение от бота.
- `/start`, `/help`, `/id`.

**Для владельца и админов**
- Сообщения приходят «карточкой»: имя, @username, ID + кнопки
  **«✍️ Ответить»** и **«🚫 Заблокировать»**.
- Ответ двумя способами: кнопка «Ответить» → следующее сообщение уходит
  пользователю; либо обычный reply на пересланное сообщение.
- Блокировка/разблокировка одной кнопкой (или `/block`, `/unblock`).
  Сообщения заблокированных тихо игнорируются.
- `/stats` — пользователи, сообщения, ответы, команда, рассылки.
- `/broadcast` — рассылка всем пользователям (запускается владельцем).
- `/addadmin`, `/deladmin`, `/admins` — несколько администраторов.
- Реакция 👌 на сообщение пользователя = «доставлено».
- Русский и английский языки — автоматически по языку Telegram.

## Быстрый старт

1. **Создайте бота** у [@BotFather](https://t.me/BotFather) и вытащите токен
   доступа CLI: BotFather → ваш бот → **Serverless** → **CLI Access**.
2. **Свяжите проект с ботом:**
   ```bash
   npx tgcloud login
   ```
3. **Задеплойте код и примените схему БД:**
   ```bash
   npx tgcloud push      # код + webhook
   npx tgcloud migrate   # таблицы в базе
   ```
4. **Назначьте владельца.** Откройте бота в Telegram, отправьте `/start`,
   затем `/claim` — первый, кто это сделает, становится владельцем.

   Надёжный вариант без «окна угона»: выполните `/claim` сразу после деплоя
   серверной командой (владелец должен сначала нажать Start у бота):
   ```bash
   npx tgcloud run handlers/message '{ chat: { id: ВАШ_TELEGRAM_ID, type: "private" }, from: { id: ВАШ_TELEGRAM_ID, first_name: "Owner", language_code: "ru" }, text: "/claim" }'
   ```
5. Напишите боту что-нибудь от второго аккаунта — сообщение должно прийти вам
   с кнопками ответа. 🎉

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | Приветствие / панель администратора |
| `/help` | все | Подсказка по ролям |
| `/id` | все | Показать свой Telegram ID и роль |
| `/claim` | кто первый | Стать владельцем бота (пока владельца нет) |
| `/stats` | админ | Статистика |
| `/block <id>`, `/unblock <id>` | админ | Управление блокировкой |
| `/admins` | админ | Список команды |
| `/addadmin <id>` | владелец | Добавить админа (можно ответом на пересланное сообщение) |
| `/deladmin <id>` | владелец | Убрать админа |
| `/broadcast` | владелец | Рассылка: команда, затем сообщение |
| `/cancel` | админ | Отменить незавершённое действие |

## Как это устроено

```
tgcloud/
├─ schema.js                 # users, incoming, relays, replies, sessions, broadcasts
├─ lib/
│  ├─ i18n.js                # словари ru/en, t() с {подстановками}
│  ├─ ui.js                  # экранирование HTML, клавиатуры, сборка текстов
│  ├─ store.js               # все запросы к БД
│  └─ relay.js               # доставка сообщений, реакции, рассылка
└─ handlers/
   ├─ message.js             # маршрутизация всех сообщений
   └─ callback_query.js      # кнопки «Ответить» / «Заблокировать»
```

Ключевые механики:

- **Доставка пользователь → админы**: сообщение копируется (`copyMessage`,
  fallback `forwardMessage`) каждому админу; в таблицу `relays` пишется пара
  «сообщение в чате админа → ID пользователя». Личное сообщение остаётся
  личным: админ видит содержимое, а не репост.
- **Ответ админ → пользователь**: кнопка «✍️ Ответить» создаёт запись в
  `sessions` — следующее сообщение админа уходит пользователю. Либо админ
  делает обычный reply на карточку/копию — маршрут находится через `relays`.
- **Альбомы**: Telegram шлёт каждый снимок отдельным апдейтом. Карточка с
  кнопками отправляется один раз (по `media_group_id`), остальные элементы
  идут следом.
- **Один владелец**: частичный уникальный индекс `uq_users_one_owner`
  (`WHERE role = 'owner'`) делает гонку двух `/claim` невозможной на уровне БД.
- **`push` ≠ миграция**: `push` везёт код, `migrate` — схему. Это две команды.

## Проверка без деплоя

Выполнить любой модуль в облаке с тестовым payload:

```bash
npx tgcloud run handlers/message '{ chat: { id: 111, type: "private" }, from: { id: 111, first_name: "Owner", language_code: "ru" }, text: "/start" }'
npx tgcloud run handlers/message '{ chat: { id: 111, type: "private" }, from: { id: 222, first_name: "User" }, text: "Привет!" }'
npx tgcloud run handlers/callback_query '{ id: "cb1", from: { id: 111 }, data: "r:222", message: { message_id: 1, chat: { id: 111 } } }'
```

## Ограничения

- **Альбомы** приходят как отдельные сообщения (не группой медиа) — учитывая,
  что Telegram отдаёт альбомы по одному апдейту, группу собрать нечем.
- **Редактирование/удаление** пользователем отправленного сообщения не
  синхронизируется с копиями у админов.
- **Рассылка** выполняется в одном обработчике и идёт последовательно
  (~10–25 сообщений/сек). Для тысяч получателей она может упереться в лимит
  времени изолята — для большой аудитории имеет смысл батчить.
- Бот работает только в **личных чатах**; в группах/каналах игнорирует всё.
